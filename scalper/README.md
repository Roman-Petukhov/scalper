# Flow Scalper

Скальпинг-бот для **Binance USDⓈ-M Futures** на основе **микроструктуры рынка (order flow)**.
Здесь нет индикаторов «из учебника» вроде EMA, RSI или MACD. Бот работает с агрессивным потоком сделок,
дисбалансом стакана, поглощением и каскадами ликвидаций.

> ⚠️ **Важно.** Это инструмент, а не «печатный станок». Прибыльность не гарантирована.
> На дефолтных параметрах бэктест на BTCUSDT **убыточен**: сигнал реален, но меньше комиссий.
> Подробности в разделе «Честно о результатах». Торгуйте реальными деньгами, только когда
> бэктест **и** paper-режим на разных периодах стабильно показывают плюс после комиссий.

## Что внутри

| Модуль | Назначение |
|---|---|
| `core/features.py` | Инкрементальные признаки: агрессивная дельта (CVD) по окнам 5/15/60с с z-score, дисбаланс стакана (OBI), microprice, реализованная волатильность (EWMA), скользящий VWAP ± σ, микро-диапазон, ликвидации, funding |
| `core/strategy.py` | Два сетапа: **Momentum ignition** и **Exhaustion fade**, плюс фильтры режима |
| `core/position.py` | Стейт-машина сделки: вход (мейкер/тейкер), перевыставление, биржевой стоп, TP, безубыток, time-stop, выход по развороту потока |
| `core/risk.py` | Размер позиции от риска до стопа, потолок плеча, дневной лимит убытка, пауза после серии убытков |
| `exchange/broker_paper.py` | Симулятор биржи: задержка, отклонение post-only (GTX), консервативные заливки лимитов, слиппедж, комиссии, reduceOnly |
| `exchange/broker_live.py` | Реальные ордера через ccxt: GTX-лимиты, STOP_MARKET (algo-ордера Binance), user-data поток + опрос, сверка позиции |
| `exchange/binance_ws.py` | Рыночные потоки с переподключением. Учитывает новое разделение Binance на `/public` (стакан) и `/market` (сделки, mark, ликвидации) |
| `backtest/` | Загрузка истории (aggTrades + SHA256), бэктест, **исследование сигналов**, запись живых потоков, отчёты и график equity |
| `notify/telegram.py` | Уведомления о сделках, алертах и дневной отчёт |

**Один и тот же код** признаков, стратегии и позиции работает в бэктесте, paper и live.
Отличается только брокер.

## Стратегия

### Признаки
- **Агрессивная дельта**: объём покупок по рынку минус объём продаж по рынку в окнах 5/15/60с, нормированный в z-score относительно последних 30 минут.
- **OBI (Order Book Imbalance)**: взвешенный дисбаланс top-10 уровней стакана, сглаженный по времени.
- **Поглощение**: сильная дельта, при которой цена почти не сдвигается (в единицах σ). Это значит, что крупный лимитный игрок забирает поток.
- **VWAP ± k·σ** за 4 часа: якорь справедливой цены.
- **Ликвидации**: кластеры принудительных закрытий за 20с.
- **Funding**: фильтр перекоса позиционирования толпы.

### Сетапы
1. **Momentum ignition (по тренду):** всплеск дельты (z₅ > 3, z₁₅ > 1.5) + стакан в ту же сторону + пробой микро-диапазона. Цена при этом не должна быть уже далеко от VWAP.
2. **Exhaustion fade (против движения):** цена за VWAP ± 2σ **или** прошёл каскад ликвидаций, агрессоры давят, а цена стоит (поглощение), стакан разворачивается.

### Выходы
TP и стоп считаются в единицах текущей волатильности. При прибыли стоп переносится в безубыток, причём с учётом комиссий.
Если сделка не в плюсе через 90с, она закрывается (time-stop). Жёсткий лимит удержания 5 минут. Резкий разворот потока против позиции тоже закрывает сделку.

### Исполнение
- **Fade** входит мейкером (post-only GTX). Это дешевле, и возврат к среднему естественно ловится лимитом.
- **Momentum** по умолчанию входит тейкером. Мейкерский лимит на пробое заливается в основном тогда, когда цена разворачивается сквозь него (adverse selection). Бэктест это подтвердил.
- **Стоп всегда стоит на бирже** (STOP_MARKET reduceOnly), поэтому защита работает, даже если бот упал.

## Порядок работы (рекомендуемый)

### 1. Исследовать сигналы (без исполнения)
```bash
python main.py study --days 14
```
Команда показывает среднее движение цены после сигнала на горизонтах 5–120с и сравнивает его с комиссией круга.
**Если среднее меньше комиссии, дальше идти бессмысленно**: никакое исполнение это не спасёт.

### 2. Бэктест
```bash
python main.py backtest --days 14
```
Отчёт показывает чистый PnL после комиссий, winrate, profit factor, expectancy, просадку и разбивку по сетапам и причинам выхода.
В `results/` сохраняются `trades.csv`, `summary.json` и `equity.png`.

Параметры удобно перебирать без правки файла:
```bash
python main.py backtest --days 14 --set strategy.momentum.z_fast=3.5 --set exits.time_stop_s=60
```
Другая монета:
```bash
python main.py --symbol SOLUSDT backtest --days 14
```

### 3. Записывать стакан
В открытом доступе нет истории стакана, поэтому бэктест на aggTrades работает **без OBI**.
Запустите запись как можно раньше:
```bash
python main.py record
```
Потом бэктест на записанных данных уже со стаканом и ликвидациями:
```bash
python main.py backtest --recorded
```

### 4. Paper-режим (живые котировки, виртуальные деньги)
```bash
python main.py paper
```
Можно параллельно писать данные: `python main.py paper --record`.

### 5. Demo-счёт Binance
Создайте ключи на demo.binance.com (API Management) и впишите их в `BINANCE_DEMO_*`.
В `config.yaml` поставьте `mode: live` и `exchange.env: demo`:
```bash
python main.py live --live
```

### 6. Mainnet
Только после стабильных результатов на шагах 2–5. Нужно `exchange.env: mainnet`, ключи `BINANCE_*`,
а при запуске бот попросит ввести `YES`. Начинайте с минимального `risk_per_trade`.

## Управление и безопасность

- **Двойная защита от случайного live**: нужны и `mode: live` в конфиге, и флаг `--live`. Для mainnet ещё и ручное подтверждение.
- **Kill switch**: создайте файл `STOP` рядом с `main.py`. Бот закроет позицию, отменит ордера и выключится. Ctrl+C работает так же.
- **Дневной лимит убытка** (по умолчанию −2%): торговля останавливается до конца UTC-суток.
- **Серия убытков** (по умолчанию 5 подряд): пауза 30 минут.
- **Сверка с биржей** каждые 2с. Если позиция закрылась на бирже без ведома бота, сделка фиксируется. Обнаруженная «осиротевшая» позиция закрывается.
- При старте live бот отменяет все открытые ордера по символу.
- Журнал сделок пишется в `logs/trades_paper.csv` и `logs/trades_live.csv`, логи лежат в `logs/`.

## Честно о результатах

Проверка на реальных данных (30.09–02.10.2026, без стакана, комиссии VIP0):

| Проверка | Результат |
|---|---|
| BTC, momentum, дефолтные пороги | после сигнала **+0.3 б.п.** (t ≈ 1.3): незначимо |
| BTC, momentum, z₅ > 5, z₁₅ > 3 | **+0.8 б.п.** на 15с (t ≈ 3.4): сигнал **реальный**, но в 5–10 раз меньше комиссии круга |
| SOL, momentum | ±0.3 б.п.: незначимо |
| BTC/SOL, fade без стакана | мало сигналов, среднее отрицательное: на одних сделках «поглощение» чаще оказывается продолжением движения |
| Бэктест BTC, дефолт | −6.2% за 3 дня, комиссии ≈ 3× валового убытка |

**Вывод:** поток сделок действительно предсказывает цену на 5–30с. Но при комиссиях VIP0 одного его мало.
Это нормальная ситуация для микроструктуры, а не баг. Каркас нужен, чтобы быстро и честно проверять такие гипотезы.

**Куда копать дальше:**
1. **Стакан (OBI, microprice)**: обычно самый сильный краткосрочный предиктор. В бэктесте на aggTrades его нет, поэтому `record` стоит запустить сразу и через 1–2 недели проверить `study --recorded`.
2. **Комиссии**: BNB-скидка, VIP-уровень, выходы мейкером. При мейкер/мейкер (4 б.п.) планка заметно ниже.
3. **Длиннее горизонт и больше цель**, чтобы движение было кратно комиссии.
4. **Больше данных**: 2–4 недели, деление на подбор и проверку (out-of-sample). Не подбирайте параметры на 3 днях.

> Сеть: в регионах, где Binance ограничивает доступ, REST API отвечает **HTTP 451**,
> и `live` работать не будет (ни demo, ни mainnet). `paper`, `record`, `study` и `backtest`
> используют только веб-сокеты и архив data.binance.vision.

## Ограничения

- Бэктест на aggTrades не видит стакан. Модель заливки лимитов консервативна: заливка только при проходе цены сквозь уровень.
- Стоп в симуляции срабатывает по цене последней сделки (в live `workingType=CONTRACT_PRICE`).
- Один символ на процесс. Для нескольких монет запускайте несколько процессов с разными `--symbol`.
- Hedge mode не поддерживается: нужен one-way режим позиций на Binance.
- **Windows**: если проект лежит очень глубоко, пути к данным могут превысить 260 символов. Держите проект в коротком пути (например, `C:\bots\scalper`) или укажите `backtest.data_dir` абсолютным коротким путём.
