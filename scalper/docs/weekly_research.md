# Еженедельное исследование стратегий

Инструкция для сессии Claude Code, которую раз в неделю запускает Routine. Её можно править как обычный файл —
следующий запуск прочитает новую версию.

## Цель

Найти одну-две **проверяемые** идеи, которые могут улучшить бота (4h — основная стратегия, 15m — на проверке) или
дать новую стратегию, проверить их на наших данных и честно записать результат. Отрицательный результат — тоже
результат: он экономит время в будущем.

## Порядок работы

1. **Подготовка.**
   - `git fetch origin main-t2qdvg weekly-research`; работать в ветке `weekly-research`. Если её нет —
     создать от `origin/main-t2qdvg`, если есть — влить в неё `origin/main-t2qdvg` (merge, не rebase).
   - Прочитать `scalper/docs/knowledge.md` целиком: что уже проверено, что сработало, что нет. Идеи из раздела
     «Фильтры, которые не сработали» не повторять, если нет принципиально нового поворота.
   - Прочитать прошлые отчёты в `scalper/docs/weekly/` (последние 4), чтобы не ходить по кругу.
2. **Поиск (веб).** Новые статьи, препринты, разборы практиков за последние месяцы о: трендовых линиях и пробоях,
   моментуме и тренде в крипте, микроструктуре (агрессоры, open interest, funding, ликвидации), режимах рынка,
   управлении риском и размером позиции, переобучении и проверке стратегий. Источники — SSRN, arXiv, журналы,
   серьёзные квант-блоги; не пересказы из соцсетей. Для каждой найденной идеи — одна строка: источник, суть, почему
   может работать (премия за риск, структурный поток, поведенческий эффект) и можно ли проверить на наших данных
   (Binance USDⓈ-M 1h/15m свечи с taker buy volume, funding, open interest 2020–2026).
3. **Выбор.** Не больше двух идей: проверяемые нашими данными, не повторяющие уже проверенное, с правдоподобной
   причиной работать. Предпочтение — улучшениям 4h-правила бота и способам заранее узнать, что стратегия перестала
   работать.
4. **Проверка.**
   - Новый скрипт `scalper/research/<имя>.py` в стиле существующих (`collect` по своей части монет через
     `research.shard.mine`, `report` по всем частям; ячейка — R на сделку через `research.smc._cell`; периоды
     `PER_ALL` из `research.oos`: 2020 / 2021 / IS / VAL / HO). Комиссии Bybit как в `research.tline`.
   - Задания `<имя>_collect` / `<имя>_report` в `scalper/research/job.sh`, `TASKS` — `"prepo <имя>"`.
   - Сначала локальная проверка на синтетических данных (данные бирж из сессии недоступны), потом push в
     `weekly-research` — это запускает workflow `research`. Дождаться: `cd scalper && python -m tools.watch_run
     --latest weekly-research`. Результат — `git show origin/research-results:runs/<run_id>/log.txt`.
   - Если прогон упал — найти причину, исправить, запустить ещё раз (не больше трёх попыток).
5. **Оценка — строго.**
   - Идея годится, только если улучшение есть в **каждом** из периодов VAL и HO и не разваливается в 2020–2021, t ≥ 2,
     сделок достаточно (≥ 5 в месяц по рынку), и после издержек ×2 знак тот же.
   - Помнить: вне выборки остаётся примерно половина бэктеста; несколько перебранных вариантов — это поиск, а не
     проверка (поправка на число попыток).
6. **Запись.**
   - Добавить вывод в `scalper/docs/knowledge.md` (раздел «Фильтры, которые не сработали» или новый, если сработало),
     2–5 строк с цифрами по периодам.
   - Отчёт `scalper/docs/weekly/<ГГГГ>-W<неделя>.md` на русском: что нашёл (со ссылками), что проверил, цифры,
     вывод, что предлагаю менять в боте (или «ничего») и что проверить на следующей неделе.
   - Commit и push в `weekly-research`. В конце сессии — короткое резюме: главный вывод и ссылка на отчёт.

## Границы

- Код бота (`scalper/trader/`), настройки на сервере и ветку `main-t2qdvg` **не менять**: только исследование и
  предложения. Внедрение — после решения владельца.
- Не создавать pull request без просьбы владельца.
- Не трогать секреты и файл `.env.local`.
- Не больше двух идей за неделю: глубина важнее количества.
